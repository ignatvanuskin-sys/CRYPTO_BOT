## НАЙДЕННЫЕ ОШИБКИ

### BUG-1 — HIGH: Кнопка «Назад» в экране ввода TP/SL не работает
- **Где:** `bot/handlers/trade.py:489` (`F.data.startswith("tpsl:")`) регистрируется РАНЬШЕ, чем `trade.py:531` (`F.data.startswith("tpsl:back:")`).
- **Что происходит:** aiogram выполняет первый подходящий хендлер. `tpsl:back:{...}` начинается с `tpsl:` → попадает в `cb_tp_sl` → `action="back"` ≠ `"skip"` → повторно ставит `awaiting: tp_sl` и рисует **тот же экран ввода TP/SL**. Новый хендлер `cb_tp_sl_back` недостижим.
- **Шаги:** Торговать → Быстрое открытие → … → «Установить TP/SL» → «Назад» → снова экран ввода (ожидался селектор «Установить/Пропустить»).
- **Фикс:** в `cb_tp_sl` первым делом: `if action == "back": return await cb_tp_sl_back(...)` — либо перенести регистрацию `tpsl:back:` ВЫШЕ `tpsl:`, либо сменить префикс на уникальный (`tpsback:`).

### BUG-2 — MEDIUM: `metrics._persist()` — синхронная запись файла на КАЖДЫЙ increment
- **Где:** `services/metrics.py:34-38`.
- **Что происходит:** `_persist()` — это sync file I/O (write+rename) внутри `event loop`. `price_poller` инкрементит по каждому тикеру (~25 раз / 2 с), `tp_sl_engine` — по каждой открытой позиции каждую секунду → десятки записей файла в секунду, блокировка цикла.
- **Дополнительно:** файл `metrics.json` лежит в `/app` (ephemeral контейнер) — на Railway без volume удаляется при рестарте, т.е. персист фактически бесполезен.
- **Фикс:** дебаунс записи (не чаще 1 раза / 10 с) + `METRICS_PATH` на volume, либо вернуть in-memory и дампить по SIGTERM.

### BUG-3 — MEDIUM: Русские команды чувствительны к регистру
- **Где:** `profile.py`, `trade.py`, `leaderboard.py` — `Command("сделки")` и т.д.
- **Проверено в рантайме:** `/сделки` → match OK, но `/СДЕЛКИ`, `/Профиль`, `/Топ` → **False**. Пользователь, набравший команду с заглавной, получит тишину.
- **Фикс:** `Command("сделки", ignore_case=True)` (aiogram поддерживает) для всех RU-алиасов.

### BUG-4 — LOW: `/top` — двойной `build_leaderboard`
- **Где:** `leaderboard.py` `cmd_top`: `_get_leaderboard_for_display()` (build #1) + `get_user_rank()` (build #2).
- **Цена:** после оптимизации это 2×3 запроса, но всё равно вдвое больше нужного; тем более что `build_leaderboard` теперь read-only. Фикс: один build → найти rank юзера в уже собранном списке (если юзер за пределами страницы — второй лёгкий запрос `COUNT` + позиция по ROI).

### BUG-5 — LOW: `_send_history` грузит ВСЕ закрытые сделки в память
- **Где:** `profile.py` `_send_history` — `SELECT ... WHERE status=CLOSED` без LIMIT для статистики (win_rate, суммы, best/worst).
- **Риск:** при 10k+ закрытых сделок — тяжёлый запрос + память. Фикс: SQL-агрегаты (`count`, `sum FILTER`, `max`, `min`) одним запросом.

### BUG-6 — LOW: `ThrottlingMiddleware` — 2 инстанса + неограниченный рост dict
- **Где:** `bot/main.py:102-103` — два отдельных экземпляра (message/callback), у каждого свой `_last_*` defaultdict, который чистится никогда → медленная утечка памяти при большом числе юзеров.
- **Фикс:** один инстанс на оба типа апдейтов + периодическая чистка записей старше N минут.

### BUG-7 — LOW: `_get_relevant_symbols` глотает ошибки БД
- **Где:** `workers/price_poller.py` — `except Exception: return DEMO_WATCHLIST` без логирования. При реальном сбое БД поллер тихо вернётся к дефолтному списку, сбой будет невидим. Фикс: `logger.exception`.

### BUG-8 — INFO: `/Сделки` в reply-клавиатуре vs «Позиции»
- `main_menu` содержит `Топ 10` / `Позиции`, но не `Сделки` (только inline в профиле). Кнопка «Позиции» показывает только OPEN — дублирует новый экран «Активные сделки». Рекомендация: переименовать reply-кнопку «Позиции» → «Сделки» (тот же новый экран) или убрать дубликат.
